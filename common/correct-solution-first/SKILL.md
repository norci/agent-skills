# 先给正确解，再谈改动范围

## 判据

方案是否正确只看一条：它要维持的不变量，是否在拥有该不变量的那一层成立。diff 大小是结果，不是选型判据。

## 输出顺序

1. 写不变量：这次改动必须始终成立的事实。
2. 写所属层：哪一层拥有这个不变量，为什么是这一层。
3. 写完整解法：该层需要的字段、设置点、翻译点、调用点与测试。
4. 写触及的位置：文件、函数、数据流。
5. 停。正确解大，就写“它大，涉及 X/Y/Z”，不缩小它。

## 不做的

- 不写更小的替代、fallback、最小 diff、“只改一处”或代价表；用户明确问更小的做法时才给。
- 不把成本挪到文本约定、重复标记、第二道闸或另一层，再把挪动后的版本叫“最小改动”。
- 不因为审查成本高就降级正确解。成本在完整解写出后单独报告，不能反过来改方案。

## 输出前自查

- 方案里出现“最小”“只改一处”“fallback”“代价”时，问一句：它是在描述结果，还是在替代正确解？替代就删。
- 若给了两个方案，问：它们是否真的不同，且都保持同一不变量？不是，就只留正确解。
