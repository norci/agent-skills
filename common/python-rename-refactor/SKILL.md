# Python 批量重命名重构

目标：把一批不达意 / 缩写之标识符改成读之即知其用之名字，且**行为逐位不变**、无遗漏、不误伤、不破持久数据。

同法亦治**换表示**（如裸元组 `(dates, values)` → 具名类）：彼虽非改名，扫描之律同 —— 见铁律 5 与坑表 18~22。

## 铁律

1. **语义级工具优先**，禁盲目 `sed` 短名：跨模块之全局名（函数 / 类 / 常量）用 `scripts/rope_rename.py`；**作用域内之局部名 / 字段用 `scripts/ast_scope_rename.py`**（rope 会改坏 `keyword` 实参名，见坑表 10）。二脚本之用法见其头部 docstring。
2. **改毕必行为对拍，且所选输入须触发所有被改代码路径**（见 §4 反例）。
3. **持久 schema 改名须同步迁移**（pickle 字段 / 数据库列 / DataFrame 列键 / 跨模块 dict 键）。
4. 数据语义字符串**不改**：交易所品种码、词元字面量、URL / 文件名模板里的占位符。
5. **换表示**（改类型 / 结构）：须按**访问模式**全扫，非按消费函数名扫 —— 旧表示支持而新表示不支持之操作（`x[0]`、`a, b = x`、`len(x)`、`x in y`、迭代）皆是漏点；同一概念之**第二实现**（同义函数）须一并归并（坑表 18、19）。

## 流程

### 1 盘点

- 扫函数签名与赋值，列候选：看不懂之缩略（`scarr` / `okfut`）、为省字母之缩写（`dur` / `num`）、单字母（`i` / `d` / `p` / `v`）。
- 分三类，处置不同：
  - **A 局部 / 参数 / 函数名**：可安全改。
  - **B 持久 schema**：dataclass 字段（入 pickle）、数据库列名、DataFrame 列键、跨模块 dict 键 —— 可改，但须迁移。
  - **C 数据语义串**：品种码 `"m" "y" "p"`、词元 `"s"` / `"b"`、f-string 里之 `{d}` 占位 —— **不改**。
- 估引用面用 `find_references`；`grep` 只答按字面找注释、字符串与 `__all__` 里的旧名，不答符号引用。
- **先查新名是否已被占用**：既查是否撞别处同名，亦查是否撞**本作用域既有参数 / 局部**（坑表 2、14）。

### 2 改名

- 按作用域选工具（见铁律 1）：局部 / 字段用 AST 器，跨模块全局名用 rope。dataclass 字段须「声明」与「用点」两类各改一次，且**以类为作用域**（坑表 13）。
- 改完立即 `pyright`，再 `grep` 旧名（含注释）。工具会漏者：dataclass 合成 `__init__` 之关键字实参（`Leg(sgn=...)`）、跨模块属性访问、`__all__` 字符串、`TypeVar("T")` 首参、`global` 声明、格式占位符（坑表 11）。
- 漏网句以词边界替换补齐：
  - 唯一模式（如 `.scarr\b`、`\bscarr=`、`\.okfut\b`）可脚本替换；
  - 通用短名（`\bw\b`、`\bcon\b`、`\bexp\b`、`\bS\b`）**禁**批量替换 —— 与别处变量 / 字符串同形，须逐处人工改。

**换表示**（如裸元组 → 具名类）另须一轮「访问模式」扫描，按语法树节点类型扫全项目，不按字面 grep：

| 旧表示支持之操作 | 语法树节点 |
|---|---|
| 下标 | `Subscript` |
| 解包 | `Assign` / `For` 之 `Tuple` 目标 |
| 属性 | `Attribute` |
| 成员 / 长度 / 迭代 | `Compare`（`In`） / `Call`（`len`） / `For.iter` |

换表示后须重建**以旧表示序列化之缓存**（pickle 里存的是旧结构，读回即报错，见坑表 7）。

### 3 迁移持久 schema

- 数据库列：`ALTER TABLE <t> RENAME COLUMN <old> TO <new>`（保数据），勿建后重灌。
- pickle / 缓存字段：字段改名令旧缓存失配 —— 确认读 miss 会自动重建（现算）；否则显式点名令用户重算。
- 顺序：**先把库列名迁到新名，再让读端用新名**；迁移与代码同批交付。
- 内存 DataFrame 列（不落库者）可直改，但产出端与读取端须同改（如 `K_{leg}` → `strike_{leg}`）。
- 写表若「富余列弃、缺列补 NULL」（不报错），则产出端之列键须与库列名逐一核 —— 类型系统不查此事（坑表 7、16）。

### 4 验证

- 项目 linter（`pyright`）`0 errors`。
- **行为对拍**：改前存基线（pickle / parquet），改后逐位比。
  - 浮点：`np.array_equal(a, c, equal_nan=True)`；
  - object / 字符串列：`np.array_equal(a.astype(str), c.astype(str))`；
  - 帧：`pd.DataFrame.equals`；序列：`index.equals` + 值全等；
  - 诊断标量：逐一 `==`（浮点容差 1e-9）。
- **覆盖全路径**（最大教训）：
  - 反例（实测）：只对「无逐日重估规则」之基线变体做对拍 —— 该路径不跑 `_step_rules`，而错恰在其中（把绝对额字段 `equity` 误写成倍数 `multiple`，名义≈1 圆 → 手数为 0 → 净值近零）。故**须选能触发每处被改代码之输入**；若一条路径无对应输入，则对其代码逐行过 diff。
  - 凡一次重命名牵涉**语义相近之两个名**（绝对值 vs 比率、两个 lengths、两个 prices），最易互换 —— 逐处 `git diff` 确认「新名是否指同一物」。
- 用 `git worktree add <tmp> HEAD` 取**改前**代码跑同一基准，作强参照。库已迁移列名时，改前代码会读旧列名而炸 —— 取一份库副本，副本内 `ALTER TABLE ... RENAME COLUMN` **反迁**回旧名，置于隔离之 `XDG_CACHE_HOME`（或等价缓存根）跑之；缓存键含 mtime，故与现树各写各的、互不污染（坑表 15）。
- 改毕 `git diff` 全过一遍：逐处问「此新名是否同一物、是否有遗漏调用点」。
- **确认静态检查之 `include` 覆盖所有被改目录** —— 漏者等于未验：本仓曾漏 `nautilus/` 与 `tests/`，
  其下两处硬伤一路不现，直到显式点名才出（坑表 20）。

### 5 收尾

- `grep` 旧名残留，**连注释 / docstring 里之指针一并改**（指针指向不存在之名即误导）。
- 另 grep 非 Name 载体：`__all__` 字符串、`TypeVar("旧名")`、`global 旧名`、SQL 列名、f-string/URL 之 `{占位符}`（坑表 11）。
- 删任何导出 / 符号（含「本包内无人用」之再导出）前，`grep -rn` 全项目 —— 含 analysis / experiments
  等约定「不保兼容」之目录；**「本包内无人用」≠ 无人用**（坑表 21）。
- 复跑复杂度工具（如 `radon cc`），确认不劣化。
- 同步下游对拍器 / 测试 / 外部脚本对旧字段之引用（若非本任务范围，须点名）。
