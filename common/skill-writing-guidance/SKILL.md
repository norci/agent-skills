# 技能文件的写法

SKILL.md 是调用契约，不是系统文档。读者是动手前的 agent，只取四样：触发判据、决定、可核对的落点、遵守的可观察形式。

## 范围：一份技能一个决定点

一份技能只覆盖一类场景，话题变宽时拆成多份。

往通用技能里加条目前，先问这条是否约束一切会话；答否，就建专用技能。判断一条规则该放哪，用两个测试：把适用主语换成某个特定场景，若语境依然成立，这条属于该场景；删掉这条，通用技能仍自洽，答是，则它是外来插入。

删掉某条后读者仍做出同样决定，就删掉那条，不留指针。

## 触发：一句写进 description

description 写「<动作>时：本质」一句。动作是 agent 当下在做的事，读者拿它与当前动作匹配；本质是这一类操作，不写具体情形。

动作写在第一句，19 字内以「。」或「：」收尾；技能目录只截这一句，其后换成 `...`。正文判据、输出物与功能介绍不进 description。

## 正文：只写怎么做

| 层 | 写什么 | 读者 |
| --- | --- | --- |
| SKILL.md | 加载哪些文件、参数、执行注意 | 决定是否加载的人 |
| 契约文件（技能另有者） | 产出什么、质量如何、路径在哪 | 已加载并执行的人 |

正文不提触发条件与适用场景，也不以「何时加载」之类标题开头。正文一级标题不与 frontmatter 的 `name` 相同，要写出这份技能的定位。

输出质量、格式、命名、路径规范，没有契约文件承载时写进 SKILL.md 正文。

一条规则要约束 agent 自己的动作，且不依赖用户消息里的词时，写进会话注入的 skill，不写 memory。memory 只在用户消息的词面命中时召回。

规则按载体分三段：文本写何时调用函数与工具行为，判定函数返回结论，流程写成可直接抄的 Lisp 代码块。函数体里不写触发条件，文本里不写判定逻辑。

## 取舍：迁移即泛化

跨文件迁移内容时，把具体案例名换成通用概念，做语义编辑，不整段复制。具体案例名属于被验证的上下文，不是可复用规则。

已整合进契约的 references 文件删掉；只有尚未整合、或独立有价值的参考才留。流程图一类辅助理解的东西放进 `docs/`。

## 落点：名字、路径与执行形式

名字必须与父目录同名，校验器按父目录核对。校验器给名字、描述、正文各一条上限；工具描述里的上限常比校验器宽，按校验器写。

目标目录不存在时写盘会建它；同名原生格式文件存在时，写 SKILL.md 被拒。写回后不必清缓存，加载器按内容摘要定位缓存条目，文本变则键变。加载器只读 SKILL.md 时，写进 references 的规则不生效；先确认加载器读哪些文件。

用户手写的技能放进 `~/code/agent-skills/` 的三棵树之一，判据见仓库 README，由外部目录加载。不要写进 harness 自己管的技能目录，那里会被更新命令覆写。来源不是用户手写的技能不可迁移。放错了位置，用整目录 `mv` 迁移，不要 `rm` 后重写。

技能里的每个代码块，按读者会用的方式加载或执行一次，通过才交付。

## 通用性：不载本机与项目信息

把一段文字搬到一个陌生项目，读者照着做还成立吗？不成立的部分改成通用形状。

观测只保留能改变动作的形状：参数与返回的形状、量级（写「单次约 30 秒」而非「30006 ms」）。举例用占位写法（`…/<图模块>.py`），不用真名。

仓内实测与结论写进该仓的计划文件、实验卷或代码注释。

## 文风

写完整的句子，每句有主语和谓语。立判据，不列细目；示例只给到能看懂的那一行。每条判据在动手那一刻可判：做，还是不做。写不成这样的句子，就是解释，删掉。

不写「为什么这么做」与「不做会错成什么样」。不写失败案例与历史沿革。不写报错原文与错误码；两种失败同形时，用退出码、返回值形状、字段是否为空分流。

## 写完核对

写完扫一遍技能目录：`/home/`、仓库名、模块名、读数，都不该出现。
