# 源码与镜像的回路

镜像里的结论只回答缺陷落在哪一层，不回答改对了没有。判绿由干净进程给出。

## 回路

1. 改源码文件。
2. 只载入本轮改过的文件，必要时连同它们的调用者；源码里删掉的定义要手工撤掉（见下）。
3. 在镜像里构造输入，跑目标行为，读结果。
4. 失败回第 1 步。
5. 通过则在干净进程里载入系统，跑对应套件。
6. 提交前在干净进程里跑完整检查。

第 3 步负责定位，第 5、6 步负责判据。

## 载入范围

载入一条定义不会重编译已经编译过的调用者，范围按改动落在哪一层定。

| 改动 | 载入范围 |
| --- | --- |
| 函数体、方法、可重载参数 | 该文件 |
| 宏、内联声明、类型声明 | 该文件与它的调用者 |
| 类定义 | 该文件；持久对象从磁盘重读后再验 |
| 泛型签名、包导出 | 整个系统强制重载 |

判据是一个问题：这个符号的调用者是否需要一起重编译。宏与内联答是，函数体答否。

## 值得进镜像的改动

长期存活的状态，以及跨层的衔接：写盘与内存各存一份状态、缓存与真值、追加与重放。这类缺口在套件里常按层各管一头，镜像里一个真实对象一步就露出来。

纯函数逻辑不进镜像，在干净进程里载入系统加断言更快。

## 先确认镜像的版本

镜像早于本轮源码时，验的是旧代码。载入前先探测本轮新增的符号、槽或变量是否存在，不存在就先载入。载入顺序决定宏与内联函数的生效版本。

## 删掉的定义要手工撤掉

载入新文件只增加定义，不删除定义。源码里删掉的方法仍挂在泛函上，删掉的函数仍可调用，它们继续按旧行为改写状态，把本轮验证抵消掉。

1. 载入本轮改过的文件。
2. 列出泛函方法：`(sb-mop:generic-function-methods #'gf)`，按限定词与特化器认出源码里已不存在的方法，用 `(find-method #'gf '(:after) (list ...) nil)` 取到后 `remove-method` 摘掉。
3. 对源码里已不存在的函数调用 `(fmakunbound 'name)`。
4. 复查：`(fboundp 'name)` 为 `NIL`，泛函方法表只剩源码里仍有的方法。

签名变更后 `load` 会报 `STYLE-WARNING ... does not match the old FTYPE proclamation`，这是重定义时的正常提示，不是失败。

## 伪造输入验证路径

在替身对象上塞入伪造值，跑真实入口，读它走了哪条分支。

- 对象用 `make-instance` 造，落盘路径指向 `/tmp`，`persisted-p` 为 `NIL`，用完删除文件。
- 伪造值先单独过对象自己的校验谓词（`...-p`），校验为真再往下走；不合法时读者一侧直接拒绝，读数全是 `NIL`，看起来像实现错误。
- 一次调用只收一个读数，多个读数合成 plist 返回；会抛错的步骤各自 `handler-case` 包住，一处失败不掩盖其余读数。
- 反事实取自 git 原文：`git show origin/master:path` 里被删掉的那段，说明同一输入在旧代码下走另一条分支。读数与原文并列才算证明，单看新代码只是自证。

样本类改动的例子：伪造一个通过校验的 sample 挂到临时会话上，调用旧代码会作废的那条入口，读 sample 是否仍是原值。

## 镜像不对应任何提交

镜像里的状态与提交对不上，事后无法重现那次验证。验证完丢弃即可；需要长期保留的改动走项目自己的落盘路径。
